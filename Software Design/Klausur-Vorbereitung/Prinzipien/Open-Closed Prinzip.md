# Open-Closed Design Prinzip

> [!important] Prinzip
> **Klassen sollen offen für Erweiterung, aber geschlossen für Veränderung sein.**

Erweitern ohne bestehenden Code zu ändern – im Kaffeehaus-Beispiel durch Decorators statt Änderung der Getränkeklassen: [[FHC02/2. Semester/Software Design/Decorator Pattern]].
